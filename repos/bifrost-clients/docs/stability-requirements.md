# 稳定性优先需求与验收

自 2026-09-14 起，以用户要求的稳定性为客户端当前首要目标。Windows 与 Android 采用同一组账号、连接和恢复原则。保留现有界面样式，性能优化和新增功能须服从这些验收要求。

1. **账号不会因读失败而显示为未激活。** 启动、前后台切换、加密存储暂时不可用、配置缺失分别处理。只有成功读取空账号，或服务端确认撤销后完成本地注销，才显示未激活。临时网络故障不能清空身份、恢复码或已验证配置。
2. **登记中断可重试。** 请求丢响应、进程被终止、配置写入中断后保留同一设备身份。通过现有设备的签名挑战恢复账号，避免自动注销已有服务端绑定。换号须走明确注销流程。
3. **配置恢复保持验证边界。** 缓存损坏或事务中断时允许重新下载；在线签名、摘要、版本下限与同版本摘要一致性仍必须通过。不能用损坏缓存继续连接，也不能因缓存损坏要求用户重新激活。
4. **连接状态按实际内核和接管状态显示。** 重复点击、断开重连、前后台切换、网络变化不得让旧任务覆盖新连接。短暂超时进入有限重试；失去接管时立即更新真实保护状态。不得靠假“已连接”掩盖故障。
5. **视频与图片优先于诊断下载。** 自动测量不得持续占用正在使用的链路。选线切换需真实正文确认、取消边界和冷却；不能以一次低延迟或一次超时来反复切换。双端遵循相同原则，允许移动网络有更低诊断预算。
6. **故障可追踪。** 保存有大小上限的本地生命周期记录，记录版本、退出类型和稳定错误码。可由用户主动分享；不包含注册码、恢复码、节点密钥、访问内容或任意异常原文。缺少用户设备日志时，不把其他手机的退出记录当成该用户的崩溃原因。

发布验收至少覆盖：原版本升级保留账号；启动及重开；短暂离线恢复；存储读失败后重试；丢失登记响应；配置提交中断；明确撤销与显式注销；同版本摘要不一致拒绝；重复连接和断开重连；真实图片/视频完整下载。长时间运行验证须写明实际持续时长；模拟时钟或单元测试不能代替连续真机运行。没有达到的项目必须在交付记录中列明。
