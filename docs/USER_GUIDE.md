# Bifrost 使用说明

适用版本：Windows **2.2.63**、Android **2.2.41**。整理日期：2026-10-11。

## 1. 下载与安装

进入 [下载页](https://github.com/endlessmaybe/bifrost/releases/latest)，展开 **Assets**。

| 设备 | 下载 |
| --- | --- |
| Windows 64 位电脑 | 文件名以 `Windows-x64.exe` 结尾的离线安装包 |
| 红米 K80 和多数新安卓手机 | `arm64-v8a.apk` |
| 旧款 32 位安卓手机 | `armeabi-v7a.apk` |
| x86_64 安卓设备 / 模拟器 | `x86_64.apk` |

Windows：双击 EXE，按提示授权，选择独立安装目录，完成后打开 Bifrost。安装目录可放在其他本地磁盘。

安卓：最低 Android 9。打开 APK，按系统提示允许当前下载应用安装软件，再完成安装。

已安装旧版：优先用软件内更新。手动安装时覆盖安装，保留账号和应用数据。安卓覆盖安装必须使用相同正式签名的 APK。

## 2. 激活账号

打开 **设置 → 设备与账户**。

| 情况 | 操作 |
| --- | --- |
| 第一次使用 | 填管理员提供的邀请码，点击激活 |
| 手机或电脑已有账号 | 在旧设备取出账号恢复码，在新设备使用恢复码激活 |
| 另一台设备生成了 `PAIR-` 码 | 在支持设备配对的入口填写；不能填到恢复码输入框 |

恢复码用于保留同一个账号。妥善保存，别发到群聊或公开截图。重新生成后，旧恢复码失效。

邀请码、恢复码和配对码用途不同。激活失败先核对输入类型、有效期与联网状态。

## 3. 第一次连接

1. 点击 **更新节点**。
2. 回到连接页，选择 **智能选线**。
3. 点击 **连接**。
4. 安卓首次连接时允许系统 VPN 授权。
5. 显示已连接后，打开网页确认真实联网。

结束使用时点 **断开**。关闭窗口或划掉手机任务与明确断开并不总是相同。

## 4. 选择模式与线路

| 需求 | 选择 |
| --- | --- |
| 日常上网 | 智能选线 |
| 统一走代理 | 全局代理 |
| 固定某个国家 / 地区 | SmartGate，手动选择出口 |
| 测试指定线路 | 在线路页手动选线，再连接 |

智能选线会维护当前源站的可用候选。SmartGate 的国家由你选择，连接期间不会自行换成别的国家。

线路页可刷新节点，选择自动优选或当前配置内的手动候选。找不到国家出口时，先更新节点，再确认管理员已发布该国家。

安卓应用分流在智能选线模式下使用：按需要将应用设为直连或代理。

## 5. 安卓 VPN、Root 与热点

**普通使用选 VPN 模式。** 允许系统 VPN 授权；持续连接需要通知与适当的后台运行权限。遇到系统省电导致断线时，检查电池限制。

Root 模式为实验功能，需要手机已有 Root。先断开，再在设置里启用 Root 模式并授权。需要界面退出后继续连接时，启用“允许持续后台连接”。明确结束时回到 Bifrost 点断开。

Root 模式不占用系统 VPN 槽位，但与其他网络工具共用时仍需检查路由和 DNS。

有热点代理设置时：

- **跟随手机代理策略**：热点设备按手机策略处理。
- **热点全部直连**：热点设备直接联网。

改完后，用热点设备打开网页验证结果。热点设置仅在对应运行模式和设备支持时生效。

## 6. 更新节点与软件

| 操作 | 作用 |
| --- | --- |
| 更新节点 | 刷新签名配置、线路与国家出口 |
| 设置 → 更新与关于 → 检查更新 | 升级 Bifrost 程序 |

管理员新增线路后先更新节点。客户端发布新版后再更新软件。

软件内更新继续使用原 Bifrost 签名发布服务。GitHub Releases 供手动下载；上传到 GitHub 不会自动修改客户端更新地址。

Windows 自动更新异常时，用当前完整离线安装包修复安装。安卓提示安装确认时按系统流程操作。旧安卓版本遇到 `BF-RELEASE-PATH`，可用同签名新 APK 覆盖安装一次。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 未激活 | 检查邀请码 / 恢复码类型，再完成激活 |
| 节点列表为空 | 更新节点；确认账号有效且管理员已发布配置 |
| 已连接但网页打不开 | 检查本机网络；更新节点；换一条可用线路；检查 VPN / Root 权限 |
| SmartGate 无国家可选 | 更新节点；确认后台已配置对应国家出口 |
| 安卓提示签名不一致 | 确认下载的是正式包；先保留数据，不要贸然卸载 |
| Windows 界面或服务异常 | 先断开；用完整离线安装包修复，保留账号数据 |
| 安卓后台断线 | 检查通知、后台运行和电池限制；Root 用户检查持续后台连接设置 |
| 恢复码失效 | 在已激活设备取出当前恢复码；重新生成过的旧码不可用 |

报错时记录平台、版本、错误码和发生步骤。日志先脱敏，不包含恢复码、账号凭据或节点链接。

## 8. 管理员操作

在原有 Bifrost 管理后台管理账号、节点和发布。GitHub 仓库用于公开客户端与下载。

常用流程：

1. 生成邀请码并交给新用户。
2. 配置源站 A / B，可导入 VMess 链接，或填写对应参数。
3. 配置国家出口，可导入 SOCKS 链接，或手动填写主机、端口与凭据。
4. 保存后点击 **发布节点配置**。
5. 让用户更新节点，检查线路和连接。

源站和国家出口各自保存。删除节点影响可变草稿；后续按后台流程发布配置。删除账号会下发撤销信息；当前双端修复了仅因撤销版本增加而误报节点更新的问题。

后台令牌、邀请码、恢复码、节点凭据和签名私钥只在原服务安全保存，不写进 GitHub。

## 9. 文件校验

下载同一 Release 的 `SHA256SUMS.txt`。在 Windows 运行：

```powershell
Get-FileHash '.\下载文件名.exe' -Algorithm SHA256
```

结果应与清单对应行一致。APK、源码包也用同样方法检查。

开发入口见 [源码与构建说明](BUILD.md)。
